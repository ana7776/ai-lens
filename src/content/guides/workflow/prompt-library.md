지난주에 회의록을 정말 깔끔하게 정리해 줬던 요청문이 있었는데, 이번 주에 다시 쓰려니 어느 대화에 있었는지 찾을 수가 없는 경험은 흔합니다. 결국 처음부터 다시 쓰다 보면 지난번만큼 결과가 좋지 않고, 무엇이 달랐는지도 알 수 없습니다. 잘 작동한 요청문은 한 번의 결과물이 아니라 다시 쓸 수 있는 작업 도구인데, 대화 기록 속에 흩어져 있으면 도구로 쓰기 어렵습니다. 이 글은 개인이나 작은 팀이 반복 업무용 요청문을 정리해 두는 방법만 다루며, 특정 메모 앱이나 프로그램의 사용법은 다루지 않습니다. 저장할 시점, 템플릿 구성, 보관 방식, 개선 방법 순서로 설명합니다. 다 읽으면 지금 자주 쓰는 요청문 하나를 템플릿으로 정리해 볼 수 있습니다.

## 언제 템플릿으로 만드나

모든 요청문을 저장할 필요는 없습니다. 아래 중 하나에 해당하면 저장할 때입니다.

- 같은 종류의 요청을 **세 번째** 쓰고 있다
- 결과가 특히 좋아서 다음에도 같은 품질을 원한다
- 매주 또는 매달 반복되는 업무에 쓴다
- 다른 사람에게 같은 작업을 부탁할 일이 있다

## 템플릿의 구성

요청문만 저장하면 나중에 "이건 언제 쓰는 거였지?", "여기에 뭘 넣어야 하지?"를 다시 고민하게 됩니다. 템플릿 하나에 아래 다섯 가지를 함께 적습니다.

| 항목 | 내용 | 예시(설명용) |
|---|---|---|
| 이름 | 무슨 작업인지 바로 알 수 있게 | 회의메모-할일표 |
| 언제 쓰나 | 사용 상황과 쓰지 말아야 할 상황 | 내부 회의 메모 정리용, 외부 회의는 공유본 따로 |
| 요청문 | 빈칸을 [ ]로 표시한 본문 | (아래 예시) |
| 확인 기준 | 결과를 받은 뒤 볼 것 | 근거 문장 칸, 미정 항목이 있는지 |
| 변경 기록 | 언제 무엇을 바꿨는지 | 10/2 반대 의견 칸 추가 |

### 템플릿 예시

```
이름: 회의메모-할일표
언제 쓰나: 내부 회의 메모를 팀 공유용 할 일 표로 정리할 때
          (개인정보가 많은 회의는 먼저 가명 처리)

요청문:
아래 [회의 이름] 메모만 근거로 정리해줘. 메모 밖의 내용은 추가하지 마.
1) 결정된 내용
2) 할 일 표: 할 일 / 담당 / 기한 / 근거 문장
3) 정해지지 않은 것
담당·기한이 메모에 없으면 '미정'으로 써.
제안을 결정으로 바꾸지 마.
[메모 붙여넣기]

확인 기준:
- 할 일마다 근거 문장이 있는가
- '미정' 항목이 실제로 메모와 맞는가
- 제안이 결정으로 바뀌지 않았는가

변경 기록:
- 2026-10-02 처음 저장
```

[ ]로 표시한 빈칸은 쓸 때마다 바꾸는 부분입니다. 빈칸이 어디인지 분명하면 다른 사람도 같은 템플릿을 쓸 수 있습니다.

## 보관 방식

어디에 보관하든 상관없지만, 아래 조건을 갖추면 오래 쓰기 좋습니다.

- **AI 서비스 밖에 보관합니다.** 메모 앱, 문서 파일, 스프레드시트처럼 내가 관리하는 곳에 두면 도구를 바꿔도 그대로 쓸 수 있습니다.
- **검색되는 이름을 붙입니다.** "작업종류-결과형식"처럼 규칙을 정하면 찾기 쉽습니다.
- **분류는 작업 기준으로 나눕니다.** 업무 / 콘텐츠 제작 / 검수처럼 내가 하는 일의 흐름에 맞춥니다.
- **템플릿에 실제 자료를 남기지 않습니다.** 예시가 필요하면 가짜 자료를 씁니다.

### 분류 예시

| 분류 | 템플릿 예시 |
|---|---|
| 업무 정리 | 회의메모-할일표, 긴문서-근거표, 메일초안-요청형 |
| 콘텐츠 제작 | 메모-블로그개요, 영상-장면구성안, 이미지-브리프 |
| 검수 | 초안-사실대조, 발행전-최종점검 |

## 템플릿을 개선하는 방법

템플릿은 한 번 만들고 끝나는 것이 아닙니다. 결과를 받은 뒤 **손으로 고친 내용**을 기록해 두고, 같은 수정이 두세 번 반복되면 그 내용을 요청문에 반영합니다.

| 반복된 수정 | 템플릿에 반영할 문장 |
|---|---|
| 매번 표 뒤의 설명 문단을 지움 | "표 외의 설명은 쓰지 마" |
| 매번 날짜 형식을 바꿈 | "날짜는 YYYY-MM-DD 형식으로" |
| 매번 존댓말로 고침 | "공유용이므로 존댓말로" |

바꾼 뒤에는 변경 기록에 날짜와 내용을 적습니다. 바꾼 버전이 오히려 결과가 나빠지면 이전 버전으로 되돌릴 수 있습니다.

## 자주 하는 실수

- **요청문만 저장하기:** 언제 쓰는지와 확인 기준이 없으면 결과를 그대로 믿게 됩니다.
- **템플릿을 너무 많이 만들기:** 비슷한 템플릿이 여러 개면 고르는 데 시간이 듭니다. 차이가 작다면 빈칸으로 합칩니다.
- **오래된 템플릿을 그대로 쓰기:** 몇 달에 한 번은 자주 쓰는 템플릿을 다시 시험해 봅니다.

## 체크리스트

- [ ] 세 번 이상 쓴 요청문을 골랐다
- [ ] 이름·용도·요청문·확인 기준·변경 기록을 적었다
- [ ] 빈칸을 [ ]로 표시했다
- [ ] AI 서비스 밖에 보관했다
- [ ] 실제 자료가 템플릿에 남지 않았다
- [ ] 반복된 수정을 템플릿에 반영하고 날짜를 남겼다

템플릿 라이브러리는 AI를 더 많이 쓰기 위한 것이 아니라, 같은 일을 매번 같은 품질로 처리하기 위한 작업 기준입니다.
