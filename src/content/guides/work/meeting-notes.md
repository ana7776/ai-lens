회의가 끝나고 메모는 잔뜩 남았는데, 누가 무엇을 언제까지 하기로 했는지 다시 물어봐야 하는 상황은 흔합니다. AI에게 "회의록 요약해줘"라고 하면 문장은 깔끔해지지만, 정작 중요한 약속과 미정 사항이 매끄러운 문장 속에 묻혀 버리기 쉽습니다. 이 글은 이미 작성된 회의 메모나 전사 텍스트를 실행 가능한 정리본으로 바꾸는 과정만 다루며, 녹음·전사 도구 선택은 다루지 않습니다. 입력 전 정리, 출력 형식 고정, 원문 대조, 공유 전 확인의 네 단계로 진행합니다. 다 읽고 나면 다음 회의 메모를 바로 붙여넣을 수 있는 요청문과 검수 기준을 갖게 됩니다.

## 1단계: 입력 전에 자료를 정리합니다

AI에 넣기 전 두 가지를 확인합니다. 하나는 **넣어도 되는 자료인가**, 다른 하나는 **근거로 삼을 만한 자료인가**입니다.

회의 내용을 외부 AI 서비스에 넣어도 되는지는 회사 규칙과 서비스의 데이터 처리 조건에 따라 다릅니다. 고객 정보, 인사 평가, 계약 조건처럼 민감한 내용은 승인된 환경이 아니라면 빼거나 일반화합니다. 구체적인 점검 항목은 [입력 전 개인정보·기밀 점검표](/work/privacy-before-input/)에 정리했습니다.

자동 전사 텍스트를 쓴다면 화자 이름과 숫자가 틀렸을 가능성을 염두에 둡니다. 전사본을 그대로 넣기보다, 최소한 숫자와 날짜가 나오는 부분은 눈으로 한 번 훑어보고 넣는 편이 안전합니다.

| 넣기 전 할 일 | 이유 |
|---|---|
| 참석자 실명을 역할명으로 바꾸기 | 불필요한 개인정보 노출을 줄입니다 |
| 회의 목적을 한 줄로 메모 맨 위에 적기 | AI가 무엇이 중요한지 판단할 기준이 됩니다 |
| 숫자·날짜 부분을 먼저 확인하기 | 전사 오류가 그대로 할 일 목록에 옮겨지는 것을 막습니다 |

## 2단계: 출력 형식을 먼저 고정합니다

요약을 요청하는 대신, 받고 싶은 정리본의 칸을 미리 정해 줍니다. 칸이 정해지면 AI가 내용을 빠뜨렸는지 한눈에 보입니다.

```
아래 회의 메모만 근거로 정리해줘. 메모 밖의 내용은 추가하지 마.

1) 회의 목적 (1문장)
2) 결정된 내용 (목록)
3) 할 일 표: 할 일 / 담당 / 기한 / 메모의 근거 문장
4) 보류되거나 정해지지 않은 것 (목록)
5) 표현이 애매해서 확인이 필요한 부분 (원문 문장과 함께)

규칙:
- 담당자나 기한이 메모에 없으면 '미정'으로 써.
- "검토해보자", "~하면 좋겠다" 같은 제안은 결정으로 바꾸지 말고 4)에 넣어.
- 반대 의견이 있었다면 지우지 말고 함께 적어.
```

핵심은 **근거 문장 칸**입니다. 할 일마다 메모의 어느 문장에서 나왔는지 붙어 있으면, 검수할 때 원문을 처음부터 다시 읽지 않아도 됩니다.

## 3단계: 원문과 대조합니다

정리본을 받았으면 공유하기 전에 아래 네 가지를 원문과 나란히 놓고 확인합니다.

1. **결정 사항이 실제 합의와 같은가.** 제안이나 의견이 결정으로 격상되지 않았는지 봅니다.
2. **담당자와 날짜가 원문과 일치하는가.** 특히 "다음 주", "월말" 같은 상대적 표현이 특정 날짜로 바뀌었다면 근거를 확인합니다.
3. **미정 항목이 사라지지 않았는가.** 정리본이 지나치게 깔끔하다면 오히려 의심해 볼 만합니다.
4. **반대 의견이나 조건이 빠지지 않았는가.** "예산이 확보되면 진행" 같은 조건이 빠지면 의미가 완전히 달라집니다.

### 예시: 이렇게 바뀌면 고칩니다

설명을 위해 만든 예시입니다.

| 메모 원문 | AI 정리본 | 판단 |
|---|---|---|
| "B안도 괜찮을 것 같다, 다음에 다시 보자" | 결정: B안으로 진행 | 결정이 아니라 보류 → 4)로 이동 |
| "자료는 김 대리가 준비" | 담당: 김 대리 / 기한: 10월 10일 | 기한은 메모에 없음 → '미정'으로 수정 |
| "견적은 300 정도" | 예산 300만 원 확정 | 추정치가 확정으로 바뀜 → 표현 수정 |

## 4단계: 공유 범위를 확인합니다

정리본을 누구에게 보낼지에 따라 남길 정보가 달라집니다. 내부 팀 공유용과 외부 거래처 공유용은 따로 만드는 것이 좋습니다.

- 외부로 보낼 정리본에는 내부 평가, 가격 협상 전략, 다른 거래처 언급을 빼야 합니다.
- 참석하지 않은 사람에게 보낼 때는 맥락 설명 한 줄을 앞에 붙입니다.
- 할 일을 담당자별로 따로 알릴 때는 [이메일 초안 가이드](/work/email-draft/)의 검수 순서를 함께 적용합니다.

## 자주 하는 실수

- **전사본 전체를 그대로 넣기:** 잡담과 중복이 많아 중요한 결정이 묻힙니다. 목적 한 줄을 맨 위에 적는 것만으로도 결과가 달라집니다.
- **요약 분량부터 지정하기:** "3줄로 요약"을 먼저 정하면 미정 항목이 가장 먼저 잘려 나갑니다. 칸을 먼저 정하고, 분량은 그다음에 조절합니다.
- **정리본을 바로 단체방에 올리기:** 결정과 담당을 원문과 대조하는 1~2분이 이후의 오해를 줄입니다.

## 회의 정리 체크리스트

- [ ] 넣기 전에 실명·민감 정보를 정리했다
- [ ] 결정 / 할 일 / 미정 칸으로 나눠 요청했다
- [ ] 할 일마다 근거 문장이 붙어 있다
- [ ] 메모에 없는 담당·기한은 '미정'으로 남았다
- [ ] 제안이 결정으로 바뀌지 않았다
- [ ] 공유 대상에 맞게 내부 정보를 정리했다

이 흐름의 목표는 회의록을 예쁘게 만드는 것이 아니라, 사람이 확인해야 할 약속과 빈칸을 놓치지 않는 것입니다. 조직에 녹음·전사·AI 사용 규칙이 있다면 이 일반 안내보다 내부 규칙을 우선합니다.
