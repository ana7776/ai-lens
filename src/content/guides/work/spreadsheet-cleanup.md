이름 띄어쓰기가 제각각이고, 날짜 형식이 섞여 있고, 같은 거래처가 세 번씩 들어간 시트를 정리해야 할 때 AI는 꽤 쓸모 있는 도우미가 됩니다. 문제는 AI가 정리해 준 표가 겉보기에 깔끔해서, 몇 줄이 사라지거나 숫자가 바뀌어도 알아채기 어렵다는 점입니다. 텍스트와 달리 데이터는 한 칸의 오류가 합계와 보고서 전체로 번집니다. 이 글은 엑셀이나 구글 시트 같은 스프레드시트 데이터를 정리하는 작업만 다루며, 통계 분석이나 시각화는 다루지 않습니다. 원본 보존, 안전한 요청 방법, 숫자로 검증하는 방법을 순서대로 설명합니다. 다 읽으면 지금 정리해야 할 시트에 바로 적용할 수 있는 작업 순서와 검증표를 갖게 됩니다.

## 시작 전: 원본을 먼저 지킵니다

모든 정리 작업은 원본 복사로 시작합니다. 시트 탭을 복제해 이름 뒤에 `_원본`을 붙여 두고, 실제 작업은 복사본에서 합니다.

그리고 AI가 만든 결과는 **기존 열을 덮어쓰지 않고 새 열에** 받습니다. 예를 들어 이름을 정리한다면 B열을 고치는 대신 C열에 `이름_정리`를 만들고, 검증이 끝난 뒤에 원래 열을 대체합니다. 이렇게 하면 무엇이 바뀌었는지 나란히 비교할 수 있습니다.

## 데이터 전체를 넣지 않아도 됩니다

AI에게 수식이나 정리 방법을 받는 데는 실제 데이터가 거의 필요 없습니다. 열 이름과, 형식만 같은 **가짜 예시 몇 줄**이면 충분합니다.

| 방법 | 입력하는 것 | 적합한 경우 |
|---|---|---|
| 수식·방법만 받기 | 열 이름 + 가짜 예시 3~5줄 | 고객 정보·매출처럼 민감한 데이터 |
| 일부만 정리 맡기기 | 식별 정보를 지운 실제 데이터 일부 | 규칙이 복잡해 예시로 설명하기 어려울 때 |
| 전체 맡기기 | 전체 데이터 | 공개 데이터이거나 승인된 환경일 때만 |

고객 이름, 연락처, 계좌 정보가 담긴 시트라면 첫 번째 방법을 기본으로 삼습니다. 무엇을 빼야 하는지는 [입력 전 점검표](/work/privacy-before-input/)에서 확인하세요.

## 요청 예시: 수식 받기

```
[목표] 거래처 시트에서 같은 거래처가 여러 번 입력된 행을 찾고 싶어.
[자료] 열 구성: A=거래처명, B=담당자, C=등록일(날짜 형식이 섞여 있음)
예시(가짜 데이터):
  (주)하늘상사 | 김OO | 2026-03-02
  하늘상사      | 김OO | 2026.3.2
  주식회사 하늘상사 | 이OO | 3/15/2026
[형식] 구글 시트에서 쓸 수식과, 각 수식이 하는 일을 한 줄씩 설명해줘.
[제약] 원본 열은 수정하지 않고 새 열에서 처리하는 방식으로.
확실하지 않은 함수 동작은 '직접 확인 필요'라고 표시해줘.
```

이렇게 받은 수식은 새 열에 넣고, 아래 검증 단계를 거친 뒤에 사용합니다.

### 자주 쓰는 정리 작업과 확인 포인트

| 작업 | AI에게 받을 것 | 직접 확인할 것 |
|---|---|---|
| 앞뒤 공백 제거 | 공백 정리 수식(예: TRIM 계열) | 정리 전후 글자 수 차이 |
| 표기 통일 | "(주)", "주식회사" 등 변환 규칙 | 규칙 때문에 다른 회사가 합쳐지지 않는지 |
| 날짜 형식 통일 | 날짜 변환 수식 | 3/4가 3월 4일인지 4월 3일인지 |
| 중복 찾기 | 중복 표시 수식(예: COUNTIF 계열) | 표시된 행을 몇 개 직접 열어보기 |
| 열 합치기·나누기 | 텍스트 결합·분할 수식 | 구분 기호가 없는 행의 처리 |

함수 이름과 문법은 엑셀과 구글 시트, 버전에 따라 조금씩 다를 수 있으니 사용하는 프로그램의 도움말에서 한 번 확인하는 것이 좋습니다.

## 숫자로 검증합니다

정리된 표를 눈으로 훑으면 "깔끔해 보이니 맞겠지"라고 판단하기 쉽습니다. 대신 원본과 결과를 아래 숫자로 비교합니다.

1. **행 개수:** 중복 제거가 아닌 작업인데 행 수가 줄었다면 무언가 사라진 것입니다.
2. **합계·평균:** 금액이나 수량 열이 있다면 원본과 결과의 합계가 같은지 봅니다.
3. **빈칸 수:** 정리 후 빈칸이 늘었다면 변환에 실패한 행이 있는 것입니다.
4. **고유값 개수:** 표기 통일 후 거래처 수가 예상보다 많이 줄었다면, 서로 다른 거래처가 합쳐졌을 수 있습니다.
5. **표본 확인:** 무작위로 5~10행을 골라 원본과 결과를 한 줄씩 비교합니다.

### 검증표 예시

설명을 위해 만든 예시입니다.

| 항목 | 원본 | 결과 | 판단 |
|---|---|---|---|
| 행 개수 | 1,240 | 1,240 | 일치 |
| 금액 합계 | 52,310,000 | 52,310,000 | 일치 |
| 날짜 빈칸 | 0 | 17 | 변환 실패 17건 → 해당 행 직접 확인 |
| 고유 거래처 수 | 318 | 276 | 줄어든 42건 중 10건 표본 확인 |

## 자주 하는 실수

- **AI가 정리해 준 표를 통째로 붙여넣기:** 행 순서가 바뀌거나 일부가 빠져도 알아채기 어렵습니다. 수식을 받아 내 시트에서 계산하는 편이 추적하기 쉽습니다.
- **날짜를 그대로 믿기:** 날짜는 지역 설정에 따라 월과 일이 뒤바뀌기 쉬운 데이터입니다. 13일 이후 날짜가 있는 행을 섞어 확인해 보세요.
- **원본 열을 바로 지우기:** 검증이 끝나기 전에는 원본 열을 숨기기만 하고 지우지 않습니다.

## 체크리스트

- [ ] 원본 시트를 복사해 두었다
- [ ] 민감 데이터는 가짜 예시로 대신했다
- [ ] 결과를 새 열·새 시트에 받았다
- [ ] 행 개수·합계·빈칸 수를 원본과 비교했다
- [ ] 표본 행을 직접 대조했다
- [ ] 검증 후에 원본 열을 대체했다

AI는 정리 규칙을 빨리 찾아주는 도구입니다. 그 규칙이 내 데이터에서 제대로 작동했는지는 숫자로 확인하는 사람이 판단합니다.
